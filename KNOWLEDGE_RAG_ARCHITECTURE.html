Intelligent Intent Routing (three paths)

Path 1 Normal Query

Greeting, capability questions, chit-chat — no retrieval.

  1. Skip embedding & vector search
  2. Call response LLM directly
  3. Example: “Good morning!” / “What can you do?”
Path 2 KB Needed

Clear factual / ops question grounded in knowledge.

  1. Embed the user question
  2. Search vector store (hybrid)
  3. Rerank → inject context → answer LLM
Path 3 KB after Query Understanding

Very large / ambiguous questions need rewrite first.

  1. LLM understands / rewrites / decomposes query
  2. Send clarified query to embedding model
  3. Then hybrid search → rerank → answer LLM

3. Cost, Latency & Quality Optimization Layer

Applied across the retrieval path (and where relevant during ingestion). Makes LLM responses faster, cheaper, and more reliable without changing the logical RAG flow.

Cross-cutting · Applied in Path 2

Intelligent Model Routing

Route each request to the right model tier: cheap/fast for intent & greetings; stronger models for hard reasoning and final grounded answers.

Where: Intent LLM · Query Understanding · Final Response

Prompt Caching

Cache stable system prompts, tool schemas, and repeated KB prefixes so subsequent calls pay less for identical prefix tokens.

Where: Repeated system + policy prompts; structured tool defs

Context Budgeting

Hard token budget for history + retrieved chunks. Prefer highest-reranked evidence; drop low-value tokens before the LLM call.

Where: Before Final Response LLM (step F)

Sliding Window

Keep only the most recent N turns (or token-bounded window) so long sessions stay within limits.

Where: Conversation history assembly

Summarization

Compress older turns or oversized retrieved docs into concise summaries to preserve meaning under budget.

Where: Long chats · Path 3 large questions · oversized chunks

Parallel LLM Calls

Run independent work concurrently (e.g. multi-query rewrite, multi-hop sub-questions) then merge results.

Where: Query Understanding · multi-facet retrieval

Structured Outputs

Force JSON / schema for intent labels, rewrite plans, and citation objects — fewer parse errors, cleaner routing.

Where: Intent Extract · Query Understanding · citations

Batching

Batch embedding jobs (ingestion) and, where APIs allow, batch small classification/routing calls.

Where: Ingestion embeddings · offline eval · bulk ingest
